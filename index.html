Security

Ready for your security review.

The questions your security team will ask, answered up front.

Your VMs stay untouched

Z-Move only reads snapshots through the cloud APIs. The source is never stopped or changed, so rolling back means carrying on with it.

Keys encrypted, then deleted

Cloud credentials are encrypted at rest, never written to logs, and deleted 30 days after the job ends.

Workers without secrets

Each temporary worker gets a token valid only for its job, opens no inbound ports and is destroyed at the end.

Encrypted in transit

TLS on every hop. Relayed disks stream in memory and are never written to disk. Azure routes go straight between the clouds.

MFA and an audit log

Administrators sign in with a second factor. Every change is recorded: who, what, when and from where.

Your own cloud, if you prefer

Run Z-Move inside your own infrastructure and keep every byte there.

FAQ

The questions we hear most

Something else? Write to hello [at] zmove.click

Do I need to install anything in my VMs?

No. Z-Move works with snapshots and volumes through the cloud APIs, using temporary workers that it creates and removes itself.

How much downtime should I plan for?

Z-Move copies a snapshot, so the source keeps running. For a consistent copy of a busy application, stop the application or the VM before the snapshot, and the downtime becomes the copy time of that VM. Between Zadara regions, replication keeps a standby up to date for shorter windows.

Which operating systems are supported?

Linux and Windows. Disks are copied block by block, so the system moves as it is. Linux VMs from Azure are adapted automatically. For Windows, check the destination's drivers before the cutover.

Does my data pass through your servers?

On Zadara ↔ Zadara and AWS ↔ Zadara routes, disks stream through the Z-Move relay over TLS, in memory, and are never written to disk. Azure routes go straight between the clouds. With a private deployment, everything stays in your infrastructure.

What happens if a migration fails?

The job log shows where and why. Workers are cleaned up and you retry from the same screen; disks already copied are reused and not billed again. The source is never touched, so a failure never puts it at risk.

Can I replicate or export instead of migrating?

Yes. Replication keeps a standby VM in another Zadara region in sync, every 30 minutes up to every 24 hours, with failover from the dashboard. Export writes a VM's disks as qcow2 or VHD to your own S3 bucket.
